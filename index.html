Study 01 · on main Credit

Statlog German Credit · scikit-learn

Credit risk decisions, not just a leaderboard

0.772
Holdout ROC-AUC for the shipped gradient boosting model. Selection used training-fold ROC-AUC, 0.793 ± 0.054, not this number.
8.9%
Holdout default rate inside the booked loans, 5 of 56, against a 30% base rate. The cutoff books 56 of 200 applicants.
$22,800
Planning cost of that book. It is the Statlog matrix at $200 a unit, not expected loss and not a P&L.
Problem
Who to approve when funding a defaulter is treated as five times as costly as turning away a borrower who would have paid.
Data
Hofmann, Statlog German Credit (1994), read as OpenML credit-g. 1,000 installment applicants, 20 attributes, no missing values, 300 defaults. personal_status mixes sex and marital status. foreign_worker encodes nationality. Both stay in the benchmark. A second cross-validation drops them.
Evaluation
Stratified 80/20 split, seed 42: 800 train, 200 holdout. Model class and cutoff are fit on the training rows only. Five-fold stratified CV picks the highest mean ROC-AUC. Each model’s cutoff minimizes Statlog cost on out-of-fold training scores. The winner is refit on the 800 and scored once on the 200.
Architecture
One scikit-learn pipeline each for logistic regression, a random forest, and histogram gradient boosting: impute, scale numerics, one-hot categories, balanced class weights. Gradient boosting is selected. The desk cutoff is 0.15. Because the weights are balanced, 0.15 is not a 15% probability.
Tradeoff
The boosting margin over the forest on training-fold AUC is about 0.0005, inside a fold standard deviation near 0.05. Holdout cost prefers the forest ($20,400) and logistic regression ($22,000). The README reports that flip and does not use it to change the shipped model. Against approving everyone, the 0.15 rule’s illustrative gap is $37,200. A 0.50 cutoff costs $27,200 on the same 200 people.
Limits
Dropping the two demographic columns moves boosting’s mean CV ROC-AUC from 0.793 to 0.786. That is not a fair-lending validation. Holdout Brier is 0.187, against 0.21 for predicting the base rate for everyone. This is a 1994 German installment file, not a 2026 U.S. application population.
Tests
On main, GitHub Actions runs Ruff and pytest. The README states 100% line coverage of src/credit_risk, including the cost arithmetic and the saved-model scorer, with no network call.

App URL, not verified as public. The README links credit-risk-prediction.streamlit.app. On 6 Nov 2026 an unauthenticated request was redirected to a Streamlit sign-in page. The still and GIF on this page are the files committed on main.

Open pull request, not merged

Pull request 3 compares the shipped booster with a logistic baseline whose penalty is chosen on the training folds. C = 0.1 wins that grid, with training-fold ROC-AUC 0.781 ± 0.057. Its holdout ROC-AUC is 0.809 and its illustrative holdout cost is $21,000, $1,800 under boosting. A stratified bootstrap of the out-of-fold gap includes zero for ROC-AUC and for cost per applicant. Study 02 · on main Lending

Lending Club sample · OpenML 43729

Loan approval prediction

0.704
Holdout ROC-AUC for logistic regression. The selection rule used cross-validated ROC-AUC, 0.670 ± 0.015, and did not see this split.
94.8%
Holdout precision at cutoff 0.64: 420 of 443 approvals were fully paid. The rule approves 23.1% of 1,916 loans.
$137,000
Planning-cost gap versus declining everyone. The scored book costs $828,400, decline-everyone $965,400, approve-everyone $1,535,000. Not a lender’s P&L.
Problem
Fund a loan or turn it away before repayment is known. Fully paid is the positive class. The planning weights are $5,000 for a false approval and $600 for a false decline.
Data
Public Lending Club sample, OpenML data id 43729, CC0. 9,578 loans, 13 predictors in the cached file, 8,045 fully paid (84.0%). The deployed score does not see credit_policy or int_rate, because both already contain a lender’s judgment. The extract has no sex, age, or race fields.
Evaluation
Stratified 20% holdout, seed 42 (1,916 loans). Model choice and the cutoff use the other 7,662 only. The same 5 stratified folds score logistic regression, a random forest, and gradient boosting, each once at defaults and once after a randomized search on ROC-AUC. The cutoff minimizes average planning cost on out-of-fold scores. The winner is refit on the training loans and scored once.
Architecture
Preprocessing sits inside the pipeline, so each fold refits it: median impute and scale for numerics, most-frequent impute and one-hot for purpose. Logistic regression is the deployed model (C=10, balanced class weight). Tuning barely moved it, from 0.669 to 0.670. After search, holdout cost among the three models differs by about $7 a loan.
Tradeoff
F1 of 0.409 is what a strict cutoff looks like when most fully paid loans are declined on purpose. The useful comparisons are the 23 false approvals out of 307 loans that were not fully paid, the 92.5% decline rate on that class, and the $71.50 planning save per holdout loan versus declining everyone. Shuffling FICO drops holdout ROC-AUC by about 0.078. Putting credit_policy and int_rate back changes cross-validated ROC-AUC by about +0.001.
Limits
Holdout Brier is 0.223, worse than guessing the 84% fully-paid rate (about 0.135), so 0.64 is not a repayment frequency. The weights are a scenario: the file has no term and no loss amount. Segment rates by FICO and purpose are screening arithmetic on fields the model is allowed to see. They are not a protected-class result, and the extract cannot support one.
Tests
On main, pytest fails if coverage of loan_approval drops under 85%. GitHub Actions runs Ruff and pytest on Python 3.12 from the cached CSV. It does not retrain and it does not call OpenML.

App URL, not verified as public. The README links loan-approval-prediction.streamlit.app. On 6 Nov 2026 an unauthenticated request was redirected to a Streamlit sign-in page.

Source on main (opens in a new tab) Pull request 3 (opens in a new tab)
Open pull request, not merged

Pull request 3 keeps logistic regression and compares it with histogram gradient boosting. Out of fold, logistic minus boosting is 0.013 ROC-AUC, 95% interval 0.003 to 0.021, which excludes zero and is what the pull request uses to deploy logistic regression. The same difference on the holdout is 0.006, interval −0.010 to 0.022, which includes zero and is not used to choose.

Isotonic regression is fit on training out-of-fold scores only. The calibrated holdout ROC-AUC is 0.703. Brier moves from 0.223 to 0.124, against 0.135 for a constant at the holdout fully-paid rate. The calibrated cutoff is 0.89. Planning cost on the same 1,916 loans is $826,400, which is $139,000 under decline-everyone. That operating point is not the one on main. Actions on the pull request passed. The hosted URL above is not described as serving this branch.

What the write-up can defend

Why the old credit-policy flag and the platform interest rate stay out of the score. Why a strict cutoff makes F1 look poor on purpose. Why the uncalibrated score should not be quoted as a repayment rate. What would have to be retuned if the $5,000 and $600 weights changed.

Study 03 · on main Fraud

OpenML credit card · data id 1597

Credit-card fraud review lab

0.679
Test PR-AUC for the selected random forest, 95% interval 0.579 to 0.788. The fraud rate is 0.172%. Accuracy is not the objective.
76 of 95
Test frauds sent to review, with 25 legitimate tickets pulled. Precision 0.752 and recall 0.800 at the cutoff locked on validation.
$10,903
Planning save versus approving every test transaction. The forest costs $6,411. Approving everything costs $17,315. The cost interval is $2,102–$12,180.
Problem
Which tickets to pull into a manual review queue. After exact duplicates are removed, approving every transaction is already 99.83% accurate, and it still pays every fraud.
Data
OpenML creditcard, data id 1597. Fingerprint 284,807 rows and 492 frauds. 9,144 exact duplicate rows removed, then 275,663 modeling rows and 473 frauds. Columns used are V1–V28 and amount. Time is not in this file. Amounts are converted at 1.10 dollars per euro before the fit. That rate is a planning input, not a 2013 spot rate.
Evaluation
Seed 42: train 165,397, validation 55,133, test 55,133, with 95 frauds in each of validation and test. Duplicates are dropped only after the fingerprint matches, so a copied ticket cannot sit in both train and test. The selection rule is locked before the test set: lowest validation dollar cost, ties broken by validation PR-AUC. Cutoffs minimize validation cost. The test set is scored once.
Architecture
Class-weighted logistic regression, an undersampled logistic regression, a random forest, histogram gradient boosting, an isolation forest fit only on legitimate training rows, and an amount-only rule. Amount is log1p-scaled with a scaler fit on the training fold. The forest wins validation cost. Its cutoff is 0.413574. The queue is about 18.3 reviews per 10,000 transactions.
Tradeoff
On the test set an undersampled logistic regression costs $5,728 and has PR-AUC 0.713, against the forest’s 0.679 and $6,411. It was not selected. The README records selection_matches_test_leader: false. A class-weighted logistic regression left at 0.50 costs $26,933, worse than approving everything. The same scores at the validation cutoff cost $6,105. Median fraud is $10.80 and median legitimate spend is $26.13, so “review the large tickets” is aimed at the wrong place. The amount rule’s best validation policy is to approve everything.
Limits
Ninety-five test frauds make a $1,000 gap look sharper than it is. Review is assumed to save the full principal. Costs are planning assumptions: $8 review, $12 false decline, $25 chargeback, on top of principal. V1–V28 are principal components. The lab does not name the original fields, and it does not brief them as merchant categories. There is no protected-class audit in this file.
Tests
On main, GitHub Actions runs Ruff and pytest on a synthetic generator, including a forced OpenML failure, so CI does not download the public file. Coverage of fraudlab fails under 85%. The published scorecard itself is from the verified public extract, not from that synthetic run.

App URL, not verified as public. The README links fraud-detection-ml.streamlit.app. On 6 Nov 2026 an unauthenticated request was redirected to a Streamlit sign-in page.

02What the repos show

Practices that are visible in the public studies. No proficiency bars, and no claim of a production seat.

Decision models

scikit-learn pipelines with the preprocessor inside the fold. Logistic regression, random forests, and histogram gradient boosting, plus an isolation forest kept as a late-label baseline on the fraud study. Cutoffs are chosen on out-of-fold or validation cost and then frozen. The write-ups report ROC-AUC or PR-AUC, a proper scoring rule where they computed one, and the cases where the holdout ranking disagrees with the precommitted choice.

Evaluation hygiene

Stratified or chronological splits, seed recorded, selection rules written before the holdout. Public files named with citations: Statlog German Credit, Lending Club OpenML 43729, OpenML credit-card 1597, UCI Online Retail. pandas for the tables. pytest, Ruff, and GitHub Actions on the three flagship repositories. The open pull requests add bootstrap intervals, a calibrated loan cutoff, and model cards. Those commits are not on main.

Finance context

The studies are written as desk decisions: a 5:1 credit matrix, a $5,000 / $600 loan scenario, and a review-queue cost account. Separately, the public profile lists tax preparation, QuickBooks Online as a QuickBooks ProAdvisor, and Double Eagle Financial LLC for small-business bookkeeping. HTML, CSS, and JavaScript for the marketing samples. Go High Level is what the profile names for the talking-website samples.
